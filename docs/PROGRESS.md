## 2026-08-21 — Фаза 1: База данных и архитектура

**Сделано:**
- Изменения Фазы 0 закоммичены и запушены в GitHub.
- Создана миграция `supabase/migrations/20260821000000_phase1_schema.sql`:
  все 8 таблиц из раздела 8 AGENT_INSTRUCTIONS.md (profiles, markers,
  marker_zones, reactions, messages, reports, live_locations,
  admin_actions) + расширение PostGIS + индексы.
- Включён Row Level Security везде:
  - свой профиль/метки/зоны — видит и меняет только владелец;
  - метки и зоны видны всем авторизованным (иначе карта бесполезна);
  - сообщения видят только участники переписки;
  - жалобы видит автор и модераторы/админы;
  - **live_locations**: включить показ себя может только подтверждённый
    18+; чужие позиции видны только пользователям 18+ и только тем,
    кто сам включил показ; по умолчанию всё выключено (opt-in);
  - забаненные не могут создавать метки, реакции, сообщения;
  - роль (user/moderator/admin) нельзя поменять самому себе.
- Добавлены служебные поля сверх ТЗ: role, banned у профилей; date_of_birth;
  мягкое удаление (deleted) у меток — понадобится модерации.

**Как проверить:**
- Открыть файл миграции в GitHub и убедиться, что он на месте.
- Применить миграцию в Supabase (SQL Editor → вставить содержимое файла
  целиком → Run), затем в Table Editor увидеть 8 новых таблиц.

**Осталось / известные проблемы:**
- Исправления первой версии миграции (2 итерации):
  1) убран запрещённый WITH CHECK из SELECT-политики сообщений;
  2) предотвращена бесконечная рекурсия RLS в политике профиля через
     security-definer функцию my_profile();
  3) убран drop trigger по несуществующей таблице — падал на чистой базе
     (42P01), каскадное удаление таблицы и так снимает триггеры.
  Файл перепроверен построчно и безопасен для повторного запуска.
- Миграция пока НЕ применена к живой базе: терминал среды не получает
  SUPABASE_ACCESS_TOKEN (нужен перезапуск воркспейса после добавления
  ключей). Пока применяется вручную заказчиком через SQL Editor.
- Автоочистка истёкших меток (TTL-cleanup) будет добавлена в Фазе 4.
- Профили видны только владельцу — для «людей рядом» и сообщений позже
  потребуется открыть чтение публичной части профиля (спросить заказчика).

**Нужно от заказчика:**
- Применить миграцию: открыть панель Supabase → SQL Editor → New query,
  вставить весь текст из `supabase/migrations/20260821000000_phase1_schema.sql`,
  нажать Run. Либо перезапустить воркспейс Freebuff — тогда попробую
  применить автоматически.

## 2026-08-21 — Фаза 0: Наведение порядка и настройка

**Сделано:**
- Осмотрен репозиторий: он практически пуст — один коммит с шаблонным
  `README.md` («# Luma») и 4 документа в `docs/`. Кода приложения,
  миграций БД, настроек Supabase в репозитории нет.
- Подключённый Supabase-проект осмотреть из среды пока невозможно:
  нет ключей доступа (env-переменные Supabase не заданы) и Supabase CLI
  не установлен. Нужны ключи от заказчика — см. «Нужно от заказчика».
- Структура приведена к виду из раздела 5 `AGENT_INSTRUCTIONS.md`:
  созданы папки `app/`, `components/`, `lib/supabase/`,
  `supabase/migrations/` (пока пустые, с файлами `.gitkeep`).
- `docs/AGENT_INSTRUCTION.md` переименован в
  `docs/AGENT_INSTRUCTIONS.md` — все документы ссылаются именно на имя
  с буквой S, теперь ссылки корректны.
- Шаблонный `README.md` («# Luma») заменён на нормальное описание
  проекта. Это была заготовка без содержимого — ничего рабочего
  не удалено.
- Создан `.gitignore`: исключает `.env`, `.env.local`, любые `.env.*`
  (кроме example-файла), `node_modules`, сборки Next.js/Vercel,
  локальные данные Supabase.
- Создан список переменных окружения. ВАЖНО: платформа Freebuff
  блокирует создание файлов с именем `.env*`, поэтому файл называется
  **`env.example`** вместо `.env.example`. Содержание то же: только имена
  переменных, без значений. При переносе на Vercel использовать именно
  эти имена.

**Как проверить:**
- Открыть репозиторий на GitHub: видна структура папок, `README.md`
  описывает проект, `env.example` содержит только имена переменных.
- Убедиться, что в репозитории нет ни одного файла с реальными ключами
  (`git ls-files | grep -i env` показывает только `env.example`).

**Осталось / известные проблемы:**
- Кода ещё нет вообще — это нормально, следующая фаза (Фаза 1) создаёт
  схему БД через миграции, затем Фаза 2 поднимает приложение Next.js.
- Имя `env.example` вместо `.env.example` — ограничение платформы
  Freebuff; при деплое на Vercel значения вставляются напрямую в
  настройки Vercel, файл в git не критичен.
- Supabase-проект заказчика пока не проверен изнутри (нет доступов).

**Нужно от заказчика:**
1. URL проекта Supabase и два ключа из панели:
   `Project URL`, `anon public key`, `service_role key`
   (Supabase → Settings → API). Их нужно вставить как переменные
   окружения (через Settings → Environment этой среды / позже в Vercel),
   НЕ в чат и не в код.
2. Токен Supabase Access Token (для управления проектом агентом):
   supabase.com → Account → Access Tokens → Generate new token.
3. Позже (Фаза 3): бесплатный ключ MapTiler (maptiler.com → Account → Keys).
